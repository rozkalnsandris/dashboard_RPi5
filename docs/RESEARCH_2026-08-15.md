## Raspberry Pi

Official Raspberry Pi documentation supports using `vcgencmd` for accurate instantaneous SoC temperature and exposes throttling state via `get_throttled`.

- Raspberry Pi hardware docs: https://www.raspberrypi.com/documentation/computers/raspberry-pi.html
- Config/temperature docs: https://www.raspberrypi.com/documentation/computers/config_txt.html

Design implication: show temperature **and** decoded throttle/under-voltage evidence, not only CPU percentage.

## Docker

Official Docker documentation confirms:

- `docker stats` / Engine stats provide container resource usage;
- Docker events provide lifecycle/health/restart/OOM events;
- container logs are available through supported logging/API paths;
- Docker daemon control is a powerful host-level security boundary and only trusted users should control it.

Sources:

- Stats: https://docs.docker.com/reference/cli/docker/container/stats/
- Events: https://docs.docker.com/reference/cli/docker/system/events/
- Logging: https://docs.docker.com/engine/logging/
- Engine API: https://docs.docker.com/reference/api/engine/
- Engine security: https://docs.docker.com/engine/security/
- Protect daemon access: https://docs.docker.com/engine/security/protect-access/

Design implication: do not expose the Docker socket/API to browser or create an arbitrary Docker proxy.

## Prometheus

Node Exporter remains an appropriate authoritative source for host/kernel hardware metrics and Prometheus remains the historical time-series layer.

- Node Exporter guide: https://prometheus.io/docs/guides/node-exporter/

Design implication: the dashboard queries/aggregates existing history rather than inventing a duplicate metrics database.

## Cloudflare

Current Cloudflare documentation supports self-hosted applications protected by Access and published through Tunnel without opening home-network inbound ports.

- Tunnel setup: https://developers.cloudflare.com/tunnel/setup/
- Self-hosted Access app: https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/
- Private web app model: https://developers.cloudflare.com/cloudflare-one/setup/secure-private-apps/private-web-app/

Design implication: `dash.rozkalns.net` sits behind Access + Tunnel and the local agent remains non-public.

## Browser terminal

xterm.js explicitly warns that embedding a browser terminal raises application security requirements, recommends restrictive privileges, avoiding third-party runtime code, treating terminal data as untrusted, and securing WebSockets with authentication/authorization and TLS.

- xterm.js docs: https://xtermjs.org/docs/
- xterm.js security: https://xtermjs.org/docs/guides/security/

Design implication: Quick Commands precede the full terminal; terminal route is isolated and non-root by default.

## Current self-hosted dashboard patterns

### Beszel

Beszel is a lightweight monitoring platform with an agent architecture, Docker CPU/memory/network history and alerts.

- https://github.com/henrygd/beszel

Useful takeaway: lightweight agent + focused monitoring works well for homelabs.

### Homepage

Homepage focuses on a fast application dashboard, service links/integrations and Docker status/stats.

- https://gethomepage.dev/
- https://gethomepage.dev/configs/services/

Community showcase discussion:

- https://github.com/gethomepage/homepage/discussions/473

Useful takeaway: service launch/navigation plus concise resource status is valuable; authentication must be handled externally.

### Homarr

Homarr combines dashboard widgets with Docker stats, log viewing and container actions.

- Docker stats: https://homarr.dev/docs/widgets/docker-containers/
- Docker integration: https://homarr.dev/docs/integrations/docker/

Useful takeaway: users value Docker stats and logs close together. For this project we deliberately postpone Homarr-style write actions until after a separate security/owner gate.

## Consolidated design conclusions

Adopt:

- health-first Overview;
- lightweight local agent boundary;
- Docker metrics + logs + events;
- Prometheus history;
- deep links instead of duplicate specialist tools;
- modern dark compact bento/grid organization;
- desktop sidebar + mobile compact navigation;
- Quick Commands before full terminal;
- Cloudflare Access/Tunnel protection.

Avoid:

- widget clutter;
- unrestricted Docker/socket exposure;
- root browser terminal;
- arbitrary file/log/shell parameters;
- duplicate metrics storage;
- premature write controls.

## Galaxy A55 mobile-specific research

Official Samsung A55 specification:

- 6.6-inch Super AMOLED;
- 1080 × 2340 FHD+;
- up to 120 Hz.

Source:

- https://www.samsung.com/uk/business/smartphones/galaxy-a/galaxy-a55-5g-awesome-navy-256gb-sm-a556bzkceub/

Important web-platform implications:

- hardware pixels are not CSS pixels;
- use `width=device-width` and responsive CSS, not 1080px phone breakpoints;
- `viewport-fit=cover` should be paired with `safe-area-inset-*`;
- use `svh`/`dvh` deliberately on mobile;
- Android virtual keyboards change the usable viewport and must be tested;
- Samsung Browser UA reduction and desktop-mode behavior make device sniffing a poor layout strategy;
- Samsung Browser and Chrome both support installed PWA experiences on Galaxy devices.
